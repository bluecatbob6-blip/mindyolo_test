# MindYOLO Train 手动运行说明

本仓库入口脚本为根目录 **`train.py`**：解析平台友好参数与 MindYOLO 专用参数，解析配置文件路径与输出目录后，**子进程调用** `mindyolo_root/train.py`（优先 `--mindyolo-root` 指向的目录，否则尝试同级 `../mindyolo-master`）。`--dataset_dir` 非空时设置环境变量 **`DATASET_DIR`**；**`--data` 非空时**设置 **`PLATFORM_DATA_YAML`**，并同时向子进程追加 **`--dataset-yaml`**（与 `mindyolo_core/train.py` 内合并逻辑一致，子进程会读取该路径并将数据段合并进 `args.data`）。

下文参数均以 `mindyolo-train-master/train.py` 中 `build_args()` 为准。与平台 JSON 一键对齐的测试脚本见仓库内 **`scripts/run_platform_train_json.py`**（读取 `mindyolo_train_config.json` / `yolov5_train_config.json` 拼命令）。

## 环境准备

1. 进入目录：`mindyolo-train-master`。
2. 安装训练依赖（见项目 `requirements.txt` 或 MindYOLO 官方说明）。
3. **`--mindyolo-root`**：默认 `./mindyolo_core`，若不存在则回退到 `../mindyolo-master`。该目录下必须存在可执行的 `train.py`。
4. **数据集**：可在模型训练 yaml 的 **`__BASE__`** 中引入 `data/*.yaml`；也可使用 **`--data`** 单独指定数据 yaml（见「数据集与双 yaml」）。注意 **`__BASE__` 合并顺序**：后引入的 yaml 会覆盖先引入的同名字段（例如 hyp 里的 `data.num_parallel_workers` 会覆盖数据集 yaml）。

---

## 一、基本运行步骤

```bash
cd mindyolo-train-master

# 方式 A：用 model_type + model_scale 选默认 yaml（相对 mindyolo_root）
python3 train.py \
  --model-type yolov5 \
  --model-scale s \
  --mindyolo-root ./mindyolo_core \
  --device-target Ascend \
  --epochs 300 \
  --per-batch-size 8 \
  --img-size 640 \
  --save-dir ./runs_train

# 方式 B：显式指定配置文件（推荐调试）
python3 train.py \
  --cfg ./mindyolo_core/configs/yolov5/yolov5n_number.yaml \
  --device-target CPU \
  --per_batch_size 2 \
  --epochs 100 \
  --save-dir ./runs_train

python3 train.py \
  --cfg /绝对路径/mindyolo_core/configs/yolov5/yolov5s.yaml \
  --device-target Ascend \
  --epochs 100 \
  --save-dir ./runs_train

python3 train.py \
  --cfg ./mindyolo_core/configs/yolov5/yolov5n_number.yaml \
  --device-target Ascend \
  --per_batch_size 4 \
  --epochs 10 \
  --save-dir ./runs_train
```

- **`--cfg`**：优先；指向存在的 yaml 文件。
- **`--config`**：次之；同样需为存在的文件路径。
- 二者都未指定时：使用 **`--model-type` + `--model-scale`** 在代码内 `MODEL_CONFIG_MAP` 中查找相对路径，并与 `mindyolo_root` 拼接为绝对路径。

## 二、参数说明（完整列表）

### 与平台 / yolov5_train_config 对齐的字段

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--dataset_dir` / `--dataset-dir` | 空 | 非空时设置环境变量 `DATASET_DIR`（绝对路径），供下游数据集路径解析使用 |
| `--best_weight` / `--best-weight` | 空 | 训练结束后尝试从 `save_dir` 下递归查找 `*best*.ckpt` 等并复制到该路径 |
| `--log-path` | 空 | 当前入口脚本未映射到子进程命令行；如需训练日志路径请用 MindYOLO yaml 或 `extra_args` |
| `--visual-path` | 空 | 非空时作为**训练输出目录**（优先级高于 `--save-dir`） |
| `--data` | 空 | 独立**数据 yaml**路径（对齐平台 JSON）。非空时设置 `PLATFORM_DATA_YAML`，并传子进程 **`--dataset-yaml`**；`mindyolo_core` 将其合并进 `args.data`（与 `--cfg` 中 `data` 叠加，外部文件字段优先）。支持 MindYOLO 格式或 YOLOv5 风格 `path/train/val/names`（见 `mindyolo_core/mindyolo/utils/config.py` 中 `merge_dataset_yaml_into_args`） |
| `--cfg` | 空 | **最高优先级**的配置文件；对应 MindYOLO **`--config`**（模型 + hyp 等，可与 `--data` 拆成「双 yaml」） |
| `--img` | 无 | 若指定，覆盖训练图像边长（映射到传给子进程的 `--img_size`） |
| `--epochs` | `300` | 训练轮数 |
| `--batch-size` | 无 | 若指定，覆盖单设备 batch（映射子进程 **`--per_batch_size`**） |
| `--optimizer` | 空 | 非空时传子进程 **`--platform-optimizer`**，覆盖 yaml 中 `optimizer.optimizer`（支持 `SGD`/`Adam`/`AdamW`/`momentum`/`nesterov`，大小写不敏感） |
| `--workers` | 无 | 非空时传子进程 **`--num_parallel_workers`**，覆盖 yaml 中 `data.num_parallel_workers` |
| `--save-period` | 无 | 非空时传子进程 **`--save_epoch_interval`**（≥1；每 N 个 epoch 保存 checkpoint，最后一轮仍会保存） |
| `--patience` | 无 | 非空时传子进程 **`--early_stop_patience`**；按验证 **map50** 早停，**需**同时 **`--extra-args --run_eval True`**（否则仅告警、不生效） |

### MindYOLO 专用 / 通用训练参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--mindyolo_root` / `--mindyolo-root` | `./mindyolo_core` | MindYOLO 源码根目录 |
| `--model_type` / `--model-type` | `yolov5` | `yolov5` / `yolov10`；在未指定 `--cfg`/`--config` 时用于选默认 yaml |
| `--model_scale` / `--model-scale` | `s` | `n`/`s`/`m`/`l`/`x`；yolov10 另含 `b`；须与 `MODEL_CONFIG_MAP` 一致 |
| `--config` | 空 | 显式 yaml；优先级**低于** `--cfg` |
| `--device_target` / `--device-target` | `Ascend` | `Ascend` / `GPU` / `CPU` 等 |
| `--is_parallel` / `--is-parallel` | `False` | 是否并行训练（字符串，由脚本解析为 True/False 传给子进程） |
| `--per_batch_size` / `--per-batch-size` | `8` | 单卡 batch；若命令行传了 `--batch-size` 则被覆盖 |
| `--img_size` / `--img-size` | `640` | 训练尺寸；若传了 `--img` 则被覆盖 |
| `--weight` | 空 | 初始权重；非空则传给子进程 `--weight`（绝对路径） |
| `--save_dir` / `--save-dir` | `./runs` | 输出目录；若传了 `--visual-path` 则被覆盖 |
| `--extra_args` / `--extra-args` | - | **剩余所有参数**透传给 MindYOLO `train.py`（需放在命令行**最后**） |

## 三、解析优先级小结

| 概念 | 优先级 / 规则 |
|------|----------------|
| 配置文件 | `--cfg` > `--config` > 默认 `model_type` + `model_scale` |
| 输出目录 | `--visual-path` 非空 > `--save-dir` |
| batch | `--batch-size`（若给）> `--per_batch_size` |
| 图像边长 | `--img`（若给）> `--img_size` |
| 数据 yaml | `--dataset-yaml` / `--data` 合并到已有 `args.data`；外部文件中 **`train_transforms`/`test_transforms` 若为 `[]` 则跳过写入**，以免冲掉 hyp 中的增强 |

## 四、数据集与「双 yaml」（对齐 YOLOv5 `--data` + `--cfg`）

- **单文件习惯**：`yolov5n_number.yaml` 在 **`__BASE__`** 中同时引入 `data/number_fullscreen.yaml` 与 `hyp.scratch-low.yaml`。
- **双文件习惯**：使用 **`configs/yolov5/yolov5n_number_split.yaml`**（仅 BASE hyp + `network`），训练时再传 **`--data /path/to/data/number_fullscreen.yaml`**，等价于原生 YOLOv5 的 **`--cfg` 模型 + `--data` 数据集** 分工。
- 子进程实际参数名：MindYOLO 使用 **`--config`** 与 **`--dataset-yaml`**（由根目录 `train.py` 从 `--cfg` / `--data` 映射），与 Ultralytics 命令字面不同，**语义对齐平台 JSON**。

---

## 五、环境变量（由入口脚本设置）

| 变量 | 何时设置 |
|------|----------|
| `DATASET_DIR` | `--dataset_dir` 非空时，值为该目录绝对路径 |
| `PLATFORM_DATA_YAML` | `--data` 非空时，值为该文件绝对路径（与 `--dataset-yaml` 二选一即可；子进程优先读命令行 `--dataset-yaml`） |

`mindyolo_core/train.py` 在解析完 `--config` 后，若存在 **`--dataset-yaml` 或 `PLATFORM_DATA_YAML`**，会调用 **`merge_dataset_yaml_into_args`** 合并数据配置。

## 六、`extra_args` 使用方式

`--extra-args` 必须出现在命令末尾，其后所有 token 原样追加到子进程，例如：

```bash
python3 train.py \
  --cfg ./mindyolo_core/configs/yolov5/yolov5s.yaml \
  --device-target Ascend \
  --save-dir ./runs \
  --extra-args --run_eval True --run_eval_interval 1
```

---

## 七、CPU 运行提示

当 `--device-target` 为 `CPU` 时，入口脚本会在未手动指定的情况下向 `extra_args` 追加：`--ms_mode 1`、`--ms_jit False`、`--ms_amp_level O0`（若这些尚未出现在 extra_args 中）。

---

## 八、macOS

在 `Darwin` 上会设置 `OBJC_DISABLE_INITIALIZE_FORK_SAFETY=YES`，减轻部分 fork 相关问题。

---

## 九、与 JSON 配置的关系

`mindyolo_train_config.json`、`yolov5_train_config.json` 用于平台表单与启动参数映射，已与《算子开发规范》对齐要点包括：`--cfg` 的 `front_type` 为 **`configFile`**、`--optimizer` 的 `type_of_list` 为 **`single`**、根级 **`minio_authorization`** 四 flag 与推理侧一致（训练入口 `train.py` 当前未消费 MinIO 四参数，仅作平台编排预留）。**入口层 flag 与 YOLOv5 平台习惯一致**；子进程为 **`mindyolo_core/train.py`**，存在 **`--config` / `--dataset-yaml` / `--device_target`** 等与 Ultralytics 字面不同的映射。**实际训练以命令行为准**；本地可用 **`python3 scripts/run_platform_train_json.py --json mindyolo_train_config.json --dry-run`** 检查拼出的命令。

## 十、最小可运行示例（复制最优权重）

```bash
python3 train.py \
  --model-type yolov5 \
  --model-scale s \
  --mindyolo-root ./mindyolo_core \
  --dataset-dir /data/my_dataset \
  --epochs 10 \
  --visual-path ./runs/exp01 \
  --best_weight /artifacts/yolov5s_best.ckpt
```

训练结束后脚本会在 `visual-path`（即本次 `save_dir`）下搜索 best checkpoint 并复制到 `--best_weight`（若找到）。

## 十一、与本仓库目录一致的 CPU 调试示例

与 `mindyolo-inference-master` 并列时，可将 `mindyolo-root` 指向本仓库内的 `mindyolo_core`，并用自定义 yaml 快速跑一轮：

```bash
export ROOT="/path/to/yolo算子开发"
export TRAIN="$ROOT/mindyolo-train-master"

cd "$TRAIN"

python3 train.py \
  --cfg "$TRAIN/mindyolo_core/configs/yolov5/yolov5n_number.yaml" \
  --epochs 1 \
  --batch-size 2 \
  --device-target CPU \
  --visual-path "$TRAIN/runs_local_manual" \
  --mindyolo-root "$TRAIN/mindyolo_core"
```

`--visual-path` 为训练输出目录；推理时使用 `mindyolo-inference-master` 的 `workflow_main.py` 并指定 `--model-path` 为此处或 `weights` 下的 ckpt 即可衔接。

### 双 yaml + `--data` 示例（与平台 `--data` 一致）

```bash
cd mindyolo-train-master

python3 train.py \
  --cfg ./mindyolo_core/configs/yolov5/yolov5n_number_split.yaml \
  --data ./data/number_fullscreen.yaml \
  --img 640 \
  --epochs 10 \
  --batch-size 2 \
  --optimizer SGD \
  --workers 2 \
  --save-period 4 \
  --patience 30 \
  --device-target CPU \
  --save-dir ./runs_train
```

终端中 **`执行命令:`** 一行应含 **`--dataset-yaml`** 指向上述数据 yaml。
