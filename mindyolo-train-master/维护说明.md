## 关键入口与职责
- `train.py`：训练主入口（项目对外唯一训练入口）；解析与 YOLOv5 平台一致的 `--dataset_dir`、`--cfg`、`--data`、`--img`、`--batch-size`、`--visual-path`、`--best_weight` 等，并映射到 MindYOLO 子进程（详见源码注释）。
- `yolov5_train_config.json` / `mindyolo_train_config.json`：前端参数渲染配置（两文件结构应与各仓库 `yolov5_train_config.json` 对齐）。

## 对内嵌 core 的本地补丁
- `mindyolo_core/mindyolo/data/dataset.py`：`COCODataset.__init__` 末尾的 `imgIds` 计算原本写死 `int(Path(stem))`，对非数字文件名会直接报错。已改为：转 int 失败时回退使用枚举索引（仅影响 COCO eval 的 image_id，训练流程不受影响）。
- `mindyolo_core/mindyolo/utils/train_step_factory.py`：`create_train_step_fn` 中 `all_finite(grads)` 在 CPU 后端会触发 `Unsupported op [get_tensor] on CPU`。已改为：当 `device_target=CPU` 时用恒 True 占位，仅供本地 CPU 调试；Ascend/GPU 路径走原 `mindspore.amp.all_finite` 不变。
- `mindyolo_core/mindyolo/models/losses/yolov5_loss.py`：`build_targets` 中 `ops.maximum(r, 1/r).max(2) < self.hyp_anchor_t` 在 PyNative 下 `.max(dim)` 返 `(values, indices)` 元组，与浮点比较报 `TypeError`。已改为 `ops.amax(ops.maximum(r, 1/r), axis=2) < self.hyp_anchor_t`，行为在两种模式下一致。

## macOS 调试相关
- `train.py`：在 macOS 下自动注入子进程环境变量 `OBJC_DISABLE_INITIALIZE_FORK_SAFETY=YES`，规避 `GeneratorDataset` fork 子进程时被 ObjC 运行时 abort 的崩溃（910C/Linux 不受影响，无副作用）。
- `train.py`：当 `--device-target=CPU` 时，自动追加 `--ms_mode 1 --ms_jit False --ms_amp_level O0` 给 mindyolo_core，避免 `@ops.constexpr` 注册的 `get_tensor` 等算子在 CPU 上无 kernel 导致图编译失败。
- 数据 yaml 建议：mac CPU 调试时把 `data.num_parallel_workers` 设为 1（已在 `data/number_fullscreen.yaml` 设置）。910C 训练时再调回默认值（如 8）。
