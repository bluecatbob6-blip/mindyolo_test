# MindYOLO Inference 手动运行说明

本文说明如何在本仓库内**手动命令行**启动三种入口：`workflow_main`（离线本地路径）、`batch_main`（MinIO 批量）、`http_main`（HTTP 服务）。参数以代码中 `argparse` 为准。

## 环境准备

1. 进入项目目录：`mindyolo-inference-master`。
2. 安装依赖：`pip install -r requirements.txt`（含 `minio`、`fastapi`、`uvicorn` 等）。
3. **MindYOLO 源码**：推理通过子进程调用上游 `mindyolo-master`（或你配置的 `--mindyolo-root`）中的脚本；请保证该路径存在且可运行。
4. **设备**：默认 `--device-target Ascend`；按本机实际改为 `GPU` / `CPU` 等（与 MindYOLO 一致）。

---

## 一、`workflow_main.py`（离线工作流：本地模型 + 本地数据）

与平台离线组件接口对齐：先 `--model-path` / `--data-path` / `--log-path`，可选 MinIO 上传。

### 运行步骤

```bash
cd mindyolo-inference-master

python3 workflow_main.py \
  --model-path /绝对路径/weights.ckpt \
  --data-path /绝对路径/图片或目录 \
  --log-path /绝对路径/logout.log \
  [--result-minio-path bucket/prefix/] \
  [--endpoint host:9000 --access-key xxx --secret-key xxx --secure false] \
  [--MindYOLO 扩展参数见下表]
```

- 第二次解析使用 `parse_known_args`，便于外层再挂其它未知参数。
- **MinIO**：仅当同时具备「结果路径 + endpoint + access-key + secret-key」时（可为命令行或上述环境变量），才会 `init_global_config` 并在推理结束后上传；否则只做本地推理。
- **`--secure`**：字符串形式的布尔，如 `true`/`false`/`1`/`0`，由 `strconv.str2bool` 解析。
- **设备与 MindSpore**：默认 `--device-target Ascend`。若本机安装的是 **仅支持 CPU** 的 MindSpore（例如 macOS、或未装昇腾驱动），必须显式传入 **`--device-target CPU`**，否则会报错 `Unsupported device target Ascend`。

### `workflow_main` 启动示例（四种常见组合）

以下均在 `mindyolo-inference-master` 目录下执行；路径请按本机修改（勿写成 `/runs_local` 这类根目录绝对路径，应使用 `./runs_local/...` 或 `$INF/...`）。

#### 情况 1：CPU — 结果仅写本地，不上传 MinIO

适用于 macOS、调试机、或 MindSpore 仅有 CPU wheel 的环境。

```bash
python3 workflow_main.py \
  --model-path ./weights/yolov5s_300e_mAP376-860bcf3b.ckpt \
  --data-path ./test_face.mp4 \
  --log-path ./runs_local/workflow.log \
  --mindyolo-root ../mindyolo-master \
  --device-target CPU \
  --backend ckpt \
  --model-type yolov5 \
  --model-scale s \
  --output-dir ./runs_infer_video_local
```

#### 情况 2：昇腾 Ascend — 结果仅写本地，不上传 MinIO

适用于已安装昇腾驱动与 MindSpore Ascend 包的机器；无需改 `--device-target` 时可省略（默认为 `Ascend`）。

```bash
python3 workflow_main.py \
  --model-path ./weights/yolov5s_300e_mAP376-860bcf3b.ckpt \
  --data-path ./戴头盔.jpg \
  --log-path ./runs_local/workflow_ascend.log \
  --mindyolo-root ../mindyolo-master \
  --device-target Ascend \
  --backend ckpt \
  --model-type yolov5 \
  --model-scale s \
  --output-dir ./runs_infer_local
```

#### 情况 3：推理结束后上传 MinIO — 命令行写全参数

需同时提供 `--result-minio-path`（形如 `桶名/对象前缀/`）与 endpoint / access-key / secret-key；`--device-target` 按机器选择 `CPU` 或 `Ascend`。

```bash
python3 workflow_main.py \
  --model-path ./weights/yolov5s_300e_mAP376-860bcf3b.ckpt \
  --data-path ./戴头盔.jpg \
  --log-path ./runs_local/workflow.log \
  --mindyolo-root ../mindyolo-master \
  --device-target CPU \
  --output-dir ./runs_infer_video_local \
  --result-minio-path face-detect-images/infer-results/ \
  --endpoint 10.10.102.63:30090 \
  --access-key admin \
  --secret-key Ab123456 \
  --secure false
```
  --data-path ./test_face.mp4 \

说明：`--result-minio-path` 第一段必须是 **MinIO 桶名**；其后可接对象前缀（建议带结尾 `/`，例如 `face-detect-images/infer-results/`）。若只写桶名 `face-detect-images`，上传对象会落在该桶**根路径**下，同样可用但更不利于按任务分子目录。

#### 情况 4：推理结束后上传 MinIO — 用环境变量（命令行不写 MinIO）

与「情况 3」等价：MinIO 连接信息与结果前缀由环境变量提供（命令行优先覆盖）。详见下表；仅导出变量而不传 `--result-minio-path` 时，会用 `MINIO_BUCKET` + `MINIO_RESULT_PREFIX`（默认 `infer-results`）拼出上传前缀。

```bash
export MINIO_ENDPOINT=10.10.102.63:30090
export MINIO_ACCESS_KEY=admin
export MINIO_SECRET_KEY=Ab123456
export MINIO_BUCKET=face-detect-images
# 可选：export MINIO_RESULT_PREFIX=infer-results
# 可选：export MINIO_SECURE=false

python3 workflow_main.py \
  --model-path ./weights/yolov5s_300e_mAP376-860bcf3b.ckpt \
  --data-path ./test_face.mp4 \
  --log-path ./runs_local/workflow.log \
  --mindyolo-root ../mindyolo-master \
  --device-target CPU \
  --output-dir ./runs_infer_video_local
```

### 使用环境变量配置 MinIO（与命令行二选一，命令行优先）

未在命令行传入对应参数时，会读取以下环境变量并用于初始化客户端与上传路径：

| 环境变量 | 说明 |
|----------|------|
| `MINIO_ENDPOINT` | 对应 `--endpoint`，如 `10.10.102.63:30090` |
| `MINIO_ACCESS_KEY` | 对应 `--access-key` |
| `MINIO_SECRET_KEY` | 对应 `--secret-key` |
| `MINIO_SECURE` | 可选；对应 `--secure`，未设且命令行也未设时按非 HTTPS 处理 |
| `MINIO_RESULT_MINIO_PATH` | 可选；完整结果前缀，如 `face-detect-images/infer-results/`（覆盖下方 bucket 组合） |
| `MINIO_BUCKET` | 可选；与 `MINIO_RESULT_PREFIX` 拼出 `--result-minio-path`（二者均未设命令行时） |
| `MINIO_RESULT_PREFIX` | 可选；默认 `infer-results`，与 bucket 拼为 `bucket/infer-results/` |

完整命令示例见上文 **「情况 4」**。等价上传前缀一般为 `face-detect-images/infer-results/`；自定义整条前缀可设 `MINIO_RESULT_MINIO_PATH=face-detect-images/my-run/`。

### 参数说明（workflow）

| 参数 | 必填 | 默认值 | 说明 |
|------|------|--------|------|
| `--model-path` | 是 | - | 模型文件绝对路径（ckpt 等） |
| `--data-path` | 是 | - | 待检测图片/视频或目录的绝对路径 |
| `--log-path` | 是 | - | 日志文件绝对路径 |
| `--result-minio-path` | 否 | - | 预测结果上传到 MinIO 的目标前缀（`bucket/path/...`） |
| `--endpoint` | 与上传联动 | - | MinIO 地址，如 `10.0.0.1:9000` |
| `--access-key` | 同上 | - | MinIO 访问密钥 ID |
| `--secret-key` | 同上 | - | MinIO 秘密密钥 |
| `--secure` | 否 | 按空则 false | 是否 HTTPS |
| `--model-type` | 否 | `yolov5` | `yolov5` / `yolov10` |
| `--model-scale` | 否 | `s` | 规模：`n`/`s`/`m`/`l`/`x`（yolov10 另含 `b`） |
| `--backend` | 否 | `ckpt` | `ckpt` / `mindir` |
| `--config` | 否 | 空 | 显式 MindYOLO yaml；空则按 model_type+scale 选默认配置 |
| `--mindyolo-root` | 否 | `../mindyolo-master` | MindYOLO 仓库根目录 |
| `--device-target` | 否 | `Ascend` | 运行设备 |
| `--img-size` | 否 | `640` | 推理输入边长 |
| `--conf-thres` | 否 | `0.25` | 置信度阈值 |
| `--iou-thres` | 否 | `0.65` | NMS IoU 阈值 |
| `--output-dir` | 否 | `./runs_infer` | 推理结果输出目录 |

## 二、`batch_main.py`（批量：MinIO 拉模型与数据，结果上传 MinIO）

### 运行步骤

```bash
cd mindyolo-inference-master

python3 batch_main.py \
  --model-minio-path bucket/path/to/model.ckpt \
  --data-minio-path bucket/path/to/image_or_folder \
  --result-minio-path bucket/path/to/output/ \
  --endpoint host:9000 \
  --access-key YOUR_KEY \
  --secret-key YOUR_SECRET \
  --secure false \
  [--model-type yolov5 --img-size 640 ...]
```

### 流程摘要

1. 初始化 MinIO，日志到默认配置（见 `mylog.init_log()`）。
2. 将模型下载到 `./models`，数据下载到 `./data`。
3. 推理输出写入 **`./result`**（代码固定，非命令行参数）。
4. 将输出文件/目录上传至 `--result-minio-path`。

### 参数说明（batch）

| 参数 | 必填 | 说明 |
|------|------|------|
| `--model-minio-path` | 是 | 模型在 MinIO 中的路径（`bucket/对象前缀`） |
| `--data-minio-path` | 是 | 待预测文件或目录在 MinIO 中的路径 |
| `--result-minio-path` | 是 | 结果上传目标前缀 |
| `--endpoint` | 是 | MinIO 服务地址 |
| `--access-key` / `--secret-key` | 是 | 访问凭证 |
| `--secure` | 是 | 是否 HTTPS（字符串布尔） |
| `--model-type` ~ `--iou-thres` | 否 | 与 workflow 表中 MindYOLO 扩展列相同含义与默认值 |

## 三、`http_main.py`（HTTP：启动前从 MinIO 拉模型）

### 运行步骤

```bash
cd mindyolo-inference-master

python3 http_main.py \
  --model-minio-path bucket/path/to/model.ckpt \
  --endpoint host:9000 \
  --access-key YOUR_KEY \
  --secret-key YOUR_SECRET \
  --secure false \
  [--model-type yolov5 --img-size 640 ...]
```

- 监听 **`0.0.0.0:8000`**（代码写死，未通过参数暴露端口）。
- 启动成功后：`POST /api/v1/inference`，表单字段上传图片（`upload_files`）；结果以文件响应返回（见 `http_api/router/inference.py`）。
- 健康检查：`GET /api/v1/ready`。

### 参数说明（http）

与 **batch** 相比：不需要 data/result 的 MinIO 路径；其余 MinIO 四参与 MindYOLO 扩展与上表一致。日志路径在代码中固定为 `/var/log/logout.log`（无命令行覆盖）。

## 四、共用说明

### MinIO 路径格式

一般为 `存储桶名/对象键前缀`；下载单文件或前缀目录的逻辑见 `myutils/myminio.py`。

### `InferenceOptions`（代码层）

推理选项由上述参数填入 `service/inference.py` 中的 `InferenceOptions`，再调用 `MindYOLOInference.run()`。JSON 配置文件（如 `mindyolo_inference_config.json`）仅供平台编排映射命令行，**Python 进程不直接读取该 JSON**。

### 模型配置映射

`model_type` + `model_scale` 会在服务内映射到 `mindyolo-master` 下默认 yaml（与 `service/inference.py` 中 `MODEL_CONFIG_MAP` 一致）；若指定 `--config` 则优先使用该 yaml。

## 五、`workflow_main` 速查

- **仅本地、不上传 MinIO**：不传 `--result-minio-path`（且不设完整 MinIO 环境变量），见第一节 **情况 1（CPU）**、**情况 2（Ascend）**。
- **上传 MinIO**：见第一节 **情况 3（命令行）**、**情况 4（环境变量）**。
- **路径**：日志与输出使用 `./xxx` 或 `$INF/xxx`，不要使用 `/xxx`（除非确实是系统绝对路径）。

## 六、与本仓库目录布局一致的示例（变量 `$INF` / `$MY`）

下列命令等价于第一节 **情况 1（CPU、仅本地）** 的图片 / 视频示例，便于在同一套环境变量下复制使用。MinIO 场景请直接在第一节 **情况 3 / 4** 上替换路径与 MinIO 参数即可。

假设四个目录并列：`mindyolo-inference-master`、`mindyolo-train-master`、`mindyolo-master`、以及可选 `weights`。先统一环境变量（按本机修改 `ROOT`）：

```bash
export ROOT="/path/to/yolo算子开发"
export INF="$ROOT/mindyolo-inference-master"
export TRAIN="$ROOT/mindyolo-train-master"
export MY="$ROOT/mindyolo-master"

# 推理权重（可换成你自己训练出的 ckpt）
export MODEL="$INF/weights/yolov5s_300e_mAP376-860bcf3b.ckpt"
```

进入推理工程目录后，**单张图片**与**视频**可分别执行：

```bash
cd "$INF"

# 图片
python3 workflow_main.py \
  --model-path "$MODEL" \
  --data-path "$INF/戴头盔.jpg" \
  --log-path "$INF/run_manual_infer.log" \
  --output-dir "$INF/runs_infer_helmet_local" \
  --mindyolo-root "$MY" \
  --device-target CPU \
  --backend ckpt \
  --model-type yolov5 \
  --model-scale s

# 视频
python3 workflow_main.py \
  --model-path "$MODEL" \
  --data-path "$INF/test_face.mp4" \
  --log-path "$INF/run_manual_infer.log" \
  --output-dir "$INF/runs_infer_video_local" \
  --mindyolo-root "$MY" \
  --device-target CPU \
  --backend ckpt \
  --model-type yolov5 \
  --model-scale s
```

说明：`--data-path` 可为单文件或目录；`--output-dir` 为本地推理写出目录；**务必保留 `--device-target CPU`**（与本机 MindSpore 一致）。训练命令见 `mindyolo-train-master/手动运行说明.md` **第十节**。若需 Ascend 或 MinIO，见第一节 **情况 2～4**。
