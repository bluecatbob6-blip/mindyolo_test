# MindYOLO 推理组件：目录结构、接口与实现对照

本文档描述 `mindyolo-inference-master` 的工程结构、平台侧 JSON 配置、各入口脚本的 CLI 参数与推理实现路径；并记录与 `yolov5-inference-master` 在 **MinIO 与入口形态** 上的对齐方式。**文末附录** 收录 YOLOv5 推理组件原文档，便于双项目对照维护。

---

## 一、目录结构（与推理相关）

```
mindyolo-inference-master/
├── workflow_main.py          # 离线推理（与 YOLOv5 同字段：本地模型 + 本地 --data-path；MindYOLO 扩展参数见下文）
├── batch_main.py             # MinIO 批量：下载模型/数据 → 推理 → 按结果路径上传 MinIO（与 yolov5 流程一致）
├── http_main.py              # FastAPI：启动前从 MinIO 拉模型；其余为 MindYOLO 专属参数
├── inference.json            # HTTP / 批量 服务形态（与 yolov5-inference 的 inference.json 一致）
├── mindyolo_inference_config.json   # 离线 workflow 组件配置：与 yolov5_inference_config.json **接口完全一致**（仅 component_name 为 MindYOLO）
├── yolov5_inference_config.json     # 与 yolov5-inference 同结构，供对照或切库
├── config/config.py          # 全局配置（MinIO 客户端、model_path、log_path、MindYOLO 推理参数）
├── myutils/                  # 日志、MinIO（与 yolov5 同源逻辑）、文件工具等
├── http_api/
│   └── router/inference.py   # POST /api/v1/inference 等（MindYOLO 推理类）
└── service/
    └── inference.py          # MindYOLOInference：调用 MindYOLO demo/predict.py 或 deploy/mslite_predict.py
```

## 二、平台 JSON 与真实 CLI 的对应关系

### 2.1 `mindyolo_inference_config.json`（离线 workflow）

与 `yolov5-inference-master/yolov5_inference_config.json` **字段与层级一致**（`output` 为空数组，`config` 仅含 `--result-minio-path`）；仅 `component_name` 为「MindYOLO通用推理」。MindYOLO 专属 CLI（如 `--model-type`、`--output-dir`）**不在本 JSON 声明**，由 `workflow_main.py` 默认值承担，或由调度在命令行追加。

| 字段位置 | `flag_name` | 含义 | 对应代码 |
|----------|-------------|------|----------|
| `input` | `--model-path` | 模型文件绝对路径（平台文案与 YOLOv5 相同；实际可为 ckpt/mindir） | `workflow_main.py` → `config.global_config.model_path` |
| `input` | `--data-path` | 待检测数据绝对路径 | `MindYOLOInference(..., image_path=data_path)`；能力见 `service/inference.py` |
| `log` | `--log-path` | 日志文件绝对路径 | `mylog.init_log(log_path)` |
| `config` | `--result-minio-path` | 预测结果在 MinIO 中的位置（平台字段） | **与 yolov5 workflow 一致：代码中 MinIO 初始化与上传未启用（预留注释块）** |
| 根节点 | `minio_authorization` | MinIO 四参数映射 | workflow 侧 **未调用** `init_global_config`（与 YOLOv5 模板一致） |

`run`：`python3` + `required_args: ["workflow_main.py"]`。

### 2.2 `inference.json`（HTTP / 批量）

| 块 | 说明 |
|----|------|
| `http_server` | 端口 `8000`，`POST /api/v1/inference`（`multipart/form-data`，字段 `upload_files`）。运行：`python3 http_main.py`。启动阶段从 MinIO 下载模型（见 `http_main.init`）。 |
| `batch_server` | 运行：`python3 batch_main.py`，MinIO 参数由调度侧拼接。 |
| `minio_authorization` | 与 `batch_main.py` / `http_main.py` 的 MinIO 四参数一致。 |

### 2.3 训练组件 JSON（与 YOLOv5 平台对齐）

训练侧平台表单使用 **`mindyolo-train-master/mindyolo_train_config.json`**（MindYOLO 默认路径前缀）与 **`mindyolo-train-master/yolov5_train_config.json`**（与 `yolov5-train-master/yolov5_train_config.json` 同结构），字段层级均为 `input` / `output` / `log` / `visualization` / `config` / `run`，与 YOLOv5 训练组件一致；MindYOLO 训练入口 `train.py` 负责将 `--cfg`、`--batch-size`、`--visual-path` 等映射到 MindSpore 训练链路。详见 `mindyolo-train-master/维护说明.md`。

## 三、各入口脚本的 CLI 与行为

### 3.1 `workflow_main.py`（离线）

- **与 YOLOv5 对齐**：双阶段 `flag_parse(first)`；`--model-path`、`--data-path`、`--log-path`；可选 `--result-minio-path` 与 MinIO 四参数；**`init_global_config` 与结果上传均为注释状态**，与 `yolov5-inference-master/workflow_main.py` 一致。
- **MindYOLO 扩展**：`--model-type`、`--model-scale`、`--backend`、`--config`、`--mindyolo-root`、`--device-target`、`--img-size`、`--conf-thres`、`--iou-thres`、`--output-dir`。
- **推理链路**：构造 `InferenceOptions` → `MindYOLOInference(options).run()` → 返回结果路径列表（内部再包装为预测输出）。

### 3.2 `batch_main.py`（MinIO 批量）

- **与 YOLOv5 对齐**：`init()` 中 `init_global_config` → `mylog.init_log()` → `down_object` 下载模型到 `./models`；`batch_inference` 中 `down_object` 下载数据 → 推理 → **`upload_file_or_folder`**；上传分支按 `result_path` 为 **str** 或 **可迭代** 分别处理（与 yolov5 相同结构）。
- **MindYOLO 扩展**：额外 CLI（`--model-type`、`--backend` 等）在 `init()` 写入 `config.global_config`；推理使用 `MindYOLOInference`，`run()` 返回路径列表，上传时对列表逐项上传。
- **辅助函数**：提供与 yolov5 同名的 `load_path`（MindYOLO 侧 **batch 流程未调用**，保留与模板一致）；单文件分支使用 `os.path.abspath(path)`，避免 yolov5 模板中单文件分支变量笔误。

### 3.3 `http_main.py`（HTTP）

- **与 YOLOv5 对齐**：`--model-minio-path` + MinIO 四参数必填；`init()` 内下载模型到 `./models` 并初始化推理类。
- **MindYOLO 扩展**：`--model-type`、`--backend`、`--mindyolo-root` 等；路由中每次请求使用 `MindYOLOInference` + `config.global_config` 中的模型路径等。

### 3.4 MinIO 工具模块 `myutils/myminio.py`

- **下载**：`down_object` / `down_folder` 与 yolov5 一致（`bucket/前缀`；目录路径以 `/` 结尾时递归列举）。
- **上传**：单文件与目录遍历上传逻辑与 yolov5 一致；目录上传时对象键后缀使用 **`os.path.relpath`** 相对 `ff_path`，避免 yolov5 模板中目录分支路径拼接笔误导致的上传错误。

## 三、各入口脚本的 CLI 与行为

### 3.1 `workflow_main.py`（离线）

**首次 `parse_args`（`init`）** 会消费：

- `--model-path`（必填）
- `--log-path`（必填）
- `--result-minio-path`（可选）
- MinIO 四参数（可选，但当前未启用 `init_global_config`）

**第二次 `parse_known_args`** 会解析：

- `--data-path`（必填）

**推理链路**：`service.inference.inference(model_path)` → `infer.run(source=data_path)`。

**`inference.run` 默认行为要点**（`service/inference.py`）：

- 后端：PyTorch `DetectMultiBackend`，权重 `model_path`，默认 `data=coco128.yaml`（用于类别名等）。
- `run` 默认 `imgsz=(640,640)`，`conf_thres=0.5`，`iou_thres=0.5`（与 MindYOLO 常用 0.25/0.65 不同，属实现差异）。
- `source` 支持 YOLOv5 惯例：图片/目录/视频/流/URL 等（见 `LoadImages` / `LoadStreams` 等）。
- 返回：`save_results` 为**带框结果图**的绝对路径列表（图片模式每张图一个路径）。

### 3.1.1 `--data-path` 支持的检测类型

YOLOv5 组件对外只有一个 `--data-path` 参数，但内部会根据字符串形态自动分发不同检测类型：

| 类型 | 判定方式 | 数据加载器 | 输出行为 |
|------|----------|------------|----------|
| 单张图片 | 后缀在 `IMG_FORMATS` 中，如 `jpg/png/bmp/webp` | `LoadImages` | 保存一张带框图片，返回结果图片绝对路径列表 |
| 图片目录 | `source` 是目录 | `LoadImages` | 遍历目录中支持的图片/视频文件，逐个保存结果 |
| 视频文件 | 后缀在 `VID_FORMATS` 中，如 `mp4/avi/mov` | `LoadImages` | 逐帧检测，写出 mp4 结果视频，返回结果视频路径 |
| 摄像头 | `source.isnumeric()`，如 `0` | `LoadStreams` | 作为视频流处理，写出 mp4 结果视频 |
| RTSP/RTMP/HTTP 流 | `rtsp://`、`rtmp://`、`http://`、`https://` 且不是直接图片/视频文件 | `LoadStreams` | 作为实时流处理，写出 mp4 结果视频 |
| URL 图片/视频文件 | URL 且后缀是图片/视频 | `check_file` 下载后再进入 `LoadImages` | 与本地图片/视频一致 |
| 截屏 | `source.lower().startswith("screen")` | `LoadScreenshots` | 截屏后检测并保存结果 |
| txt 列表 | `source.endswith(".txt")` | `LoadStreams`（YOLOv5 原逻辑） | 作为流列表处理 |

核心实现步骤：

1. `workflow_main.py` 读取平台传入的 `--data-path`。
2. `service.inference.inference.run(source=data_path)` 将 `source` 转字符串。
3. 根据 `source` 判断 `is_file/is_url/webcam/screenshot`。
4. URL 文件先通过 `check_file` 下载到本地。
5. `webcam=True` 时使用 `LoadStreams`，`screenshot=True` 时使用 `LoadScreenshots`，其余使用 `LoadImages`。
6. 每帧/每图执行预处理、模型前向、NMS、坐标缩放、绘框。
7. 图片保存为带框图片；视频/流使用 `cv2.VideoWriter` 保存为 mp4。
8. 返回 `save_results`，即输出图片/视频文件路径列表。

### 3.2 `batch_main.py`（MinIO 批量）

**`init` 首次解析**（必填为主）：

- `--model-minio-path` / `--data-minio-path` / `--result-minio-path`
- `--endpoint` / `--access-key` / `--secret-key` / `--secure`

流程：初始化 MinIO → 下载模型到 `./models` → 第二次解析同上（无额外参数）→ `batch_inference`：下载数据 → `inference.run(source=本地路径)` → 将 `result_path`（单路径或列表）上传回 MinIO。

**已知代码问题**：`load_path` 中 `os.path.isfile(path)` 分支写了 `result.append(os.path.abspath(f))`，`f` 未定义，若走到单文件分支会异常；目录枚举分支正常。

### 3.3 `http_main.py`（HTTP）

**`init` 解析**：

- `--model-minio-path`（必填）
- MinIO 四参数（必填）

流程：初始化 MinIO → 日志固定 `/var/log/logout.log` → 下载模型到 `./models` → `inference.init_infer_class(model_path)` → `uvicorn` 监听 `0.0.0.0:8000`。

**路由**（`http_api/router/inference.py`）：

- `POST /api/v1/inference`：`upload_files` 或 `structured_data` 二选一；文件模式保存后取首张路径 `infer.run(source=data_source)`，返回 `FileResponse(result[0])`。
- `structured_data` 分支假定 `infer.run` 返回 CSV 路径并 `pd.read_csv`，与当前 `inference.run` 返回图片路径列表**不一致**，该分支易失败（历史模板遗留）。

## 五、与 MindYOLO 推理组件的差异摘要（对齐时参考）

| 维度 | yolov5-inference-master | mindyolo-inference-master（现状） |
|------|-------------------------|-----------------------------------|
| 推理引擎 | PyTorch Ultralytics | MindSpore：`demo/predict.py`（ckpt）或 `deploy/mslite_predict.py`（mindir） |
| 离线输入 | `--data-path` 任意 YOLOv5 source | 单图 `--image-path`（及 wrapper 映射的 `--image_path`） |
| 组件 JSON | `yolov5_inference_config.json` + `minio_authorization` | `mindyolo_inference_config.json` 与 yolov5 **接口一致**（仅 `component_name` 不同）；同仓库 `yolov5_inference_config.json` 可与 YOLOv5 项目互换对照 |
